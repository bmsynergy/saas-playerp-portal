# Portal English / Spanish

All interface copy belongs in `src/locales/en.ts` and `es.ts`. Support and the
printed recovery label have typed bilingual catalogues in `src/locales/support.ts`
and `label.ts`. The existing maintenance message catalogue remains shared with the
maintenance email; its bilingual entries are checked without changing that contract.

Use `useLocale().t(key)` at render time. Persist message **keys and parameters** or
an error cause, not the result of `t(...)`; otherwise an already visible message
will remain in the previous language. Format presentation numbers and dates with
the selected locale. Do not format identifiers, revisions, versions, serials, user
content or API payload values. Server error codes must map to local copy; unknown
codes use a localized fallback. Exact diagnostics belong in technical disclosures.

`npm run check:i18n` also runs before `npm run build`. It checks dictionary key
parity, empty entries, duplicate entries, interpolation parameters, direct and
conditional translation references, and finite TypeScript unions in template keys.
It scans every TS/TSX source outside the translation catalogues for JSX text,
visible/accessibility attributes, label/title/message metadata, inline language
branches, DOM text assignments and literal feedback messages. It also rejects
translated feedback stored directly in state and unreviewed identical EN/ES copy.

Names, language autonyms, units and syntax examples have exact file/text exceptions
in `scripts/i18n-exceptions.json`; identical legitimate dictionary values are in
`i18n-shared-values.json`. Each exception requires a reason and stale exceptions
fail. These lists are not a baseline for untranslated UI. Do not add an exception
for ordinary interface copy or a frozen translated message.

Static checking cannot infer arbitrary runtime strings or every helper's data flow.
Review new presentation helpers and mappings for open-ended server values. The
`tests/i18n.test.ts` regression suite injects missing translations and new literals,
checks frozen feedback detection and localized backend errors/file sizes. The
browser checks exercise visible states, locale persistence and layout:

```sh
npm test
npm run build
# Start the test server on the assigned test port, then stop it after testing.
npm run dev -- --port 18799
node tests/i18n-browser.mjs
node tests/i18n-device-browser.mjs
```

Both browser scripts accept `PORTAL_TEST_ORIGIN=https://playerp.dev.bmore.app`.
They use the actual frontend with intercepted synthetic Auth/API responses and
block other destinations. They never establish live authorization or make real
backend writes. Reports and screenshots default to ignored `test-results/`
folders; select evidence goes under the work's evidence directory.
